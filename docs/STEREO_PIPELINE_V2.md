# 立体视觉生成方案 V2

目标是改善左右眼的遮挡背景、轮廓、纹理一致性和视频稳定性。采用共享分层场景生成两眼，并将 DLSS5 作为可评估、可回退的增强阶段。本文是实施方案，尚未完成的模块和效果不作为已验证能力。

## 已有证据与修正

- 本机 native carrier 能运行；616.56 与 616.64 的已测输出一致。实际调用包含 DLAA、RenoDX、Feature18 和合成，因此整条路径的差异不能自动归因于 Feature18 单独贡献。
- 深度用于外部几何生成。Distill Any Depth small 输出相对深度，不能未经标定当成米制深度；按图 min/max 归一化会在视频中产生视差呼吸。
- 对当前 harness 设置 ControlMask 未观察到效果，尚未证明参数穿过 SR/add-on 到达 Feature18。不能据此认定 DLL 内的 ControlMask 功能不存在。
- host 的 `where(valid, base, dlss_output)` 是独立的输出选择。native 静态公式含 `blend_scale`，mask=1 不一定完全返回 base，两者并不等价。carrier 返回的图也不能直接称为未混合的 neural 张量。
- 57 KB portable checkpoint 是在十张合成样本上训练的小型代理网络；它没有证明保留 DLSS5 的补洞能力。本方案的 DLSS5 实验使用 native carrier。
- 旧平面 oracle 用 `roll` 指定边界之外的参考纹理，验证的是周期平面外推。洞在右侧最后 16 列，后续评估必须读取几何产生的 mask；不能手工把左侧 16 列当作洞。旧正式 runner 的洞区来自几何 mask，保留其结果，但不把它解释为真实遮挡恢复。

## 推荐架构

```text
中心图像 / 游戏帧 + 深度 + 相机参数
  → 深度稳定、轮廓与透明区域处理
  → 建立共享前景/背景层、置信度与可见性
  → 预测两眼需要的背景区域，优先从历史观测补回
  → 在背景层补全剩余未知区域
  → 可选：DLSS5 增强共享图像/背景层
  → 分别渲染左眼和右眼，产生各自 SourceMap、Depth、HoleMask
  → 可选：DLSS5 局部修复候选 + 外部置信度合成
  → 双眼一致性、边缘和闪烁检查
  → SBS/TAB + 深度/MV/置信度诊断输出
```

### 1. 几何决定哪些像素可信

游戏能提供深度和相机矩阵时直接使用；照片继续使用 Distill Any Depth small，显式配置相对深度到视差的映射、最大视差和零视差平面。默认从中心视图向两眼各分配半个基线，同时保留左眼固定模式用于回归。

使用带覆盖率的亚像素 splat 或深度网格渲染替换逐点取整。网格在深度跳变处断开，避免三角形跨越前后景。先区分四类无覆盖区域：采样裂缝、真正反遮挡、图像边界外推、深度不确定区。它们分别记录 mask，不能合并后只报一个洞比例。

真实前景不向背景洞扩散。细杆、头发和半透明轮廓保留软覆盖率；无法可靠分层时降低局部视差或神经修改权重。不能在轮廓两侧直接平滑视差，否则会产生橡皮片效果。

### 2. 先补共享背景，再投影两眼

根据双眼视差范围，计算遮挡边界后需要额外露出的背景带。背景带宽由前后景视差差值决定，并留插值余量。

补全信息按优先级选择：

1. 同一背景表面在历史帧中实际出现过的像素，经过深度和相机重投影验证后复用。
2. 小采样裂缝使用同一深度层插值；窄反遮挡带使用背景侧传播、纹理块匹配或梯度延拓。
3. 宽洞交给专门的图像补全阶段。其模型在独立验证集选型；生成结果落在共享背景层，供两眼一致采样。

分层数据同时保存颜色、相对/米制深度、观测或生成来源、置信度和时间戳。未知背景属于推测内容；禁止为了填满图像而赋予其与真实观测相同的置信度。照片边框、字幕、HUD 单独按屏幕平面合成，避免深度模型把边框变成立体前景。

### 3. DLSS5 的三个候选位置

| 路径 | 操作 | 预期价值与验证重点 |
|---|---|---|
| A：共享增强 | 在分眼之前对中心图像或已补全背景层运行一次 DLSS5，然后两眼采样同一结果 | 共享新增细节；检查增强是否改变轮廓，以及同一平面上的色调和材质是否一致 |
| B：补全后局部修复 | 对完整预填充的左右眼产生 DLSS5 候选，只在低置信度背景和背景侧接缝合成 | 检查是否减少拉伸、条纹和接缝，同时保持观测区不变 |
| C：跨眼虚拟历史 | 固定左眼 reset，再以右眼和几何 MV 运行；反方向也做对照 | 沿用原 PLAN 作为实验分支，检查是否比单帧修复更好、是否产生眼间不对称 |

优先实现 A 与 B，C 保留为对照。若 A 改善材质但 B 损坏接缝，部署时只启用 A。任何路径的启用都由对照结果决定，不能为了使用 DLSS5 强制保留负收益阶段。

### 4. 时序状态与 Motion Vector

视频优先保留真实时间维度：共享视图使用自己的 native session；如果启用分眼修复，左右眼各自维护 session。不得把 `L_t → R_t → L_(t+1)` 当成普通视频流连续提交。跨眼虚拟历史实验必须与这些 session 隔离。

有效对应使用 `MV(p_current) = p_previous - p_current`，由相机和深度生成，并在平面测试中校准符号、像素尺度、Y 轴与 jitter。真正新露出的背景没有上一帧对应，应标无效；若 ABI 只能接受向量，则零向量仅作为回退值，外部置信度必须保留无效信息。

当前 harness 在启动时上传一次 motion，无法严格执行“左眼零 MV、右眼几何 MV”。实施前增加逐帧 MOTION/DEPTH 上传、输入回读和日志，再校准。镜头切换、分辨率变化、深度映射变化和大范围背景重生成时 reset；稳定生成的背景沿用缓存，避免每帧独立生成纹理。

### 5. 外部合成与验收回退

令 B 为几何加背景补全结果，D 为 carrier 输出，A 为外部修复权重：

```text
output = B + A * (D - B)
A = repair_region * geometry_confidence * temporal_confidence * stereo_confidence * strength
```

权重只在背景层内部羽化，不跨越真实前景轮廓。观测可信区 A=0，修复区也不默认 A=1。输出同时保存 B、D、A，便于检查收益来自预填充还是 DLSS5。native ControlMask 若未来验证可用，作为另一个控制接口单独标定，不直接用上述 A 替换它。

先检测非有限值、过大局部色偏、轮廓位移、眼间残差不一致和时间跳变；失败区域回退到 B。置信度只能使用输入、历史和候选结果，禁止使用测试真值挑选权重。验收数据上的参数冻结后，才进入独立测试集。

## 能够判定收益的实验

### 数据

- 几何单元用例：常深度平面、前景矩形、细杆、斜面、零基线。检查投影、Z-buffer、mask、MV 和亚像素覆盖。
- 有真值的分层场景：完整背景纹理 + 前景遮挡物，分别渲染中心、左眼、右眼。补全流程只能访问中心图及其可见深度；隐藏背景只供评价。加入不同洞宽、材质和轮廓。
- 视频：相机横移、物体移动、背景先露出后遮挡、镜头切换，检验历史是否回收了真实背景。
- 实拍/游戏图片：沿用公开素材并补充室内、人物、文字和细结构；没有右眼真值时只评价可见区一致性和观感，不报“重建精度改善”。

### 消融

| 编号 | 路径 | 回答的问题 |
|---|---|---|
| B0 | 取整 shift + 行最近邻 | 旧基线 |
| B1 | 改善几何 + 背景侧补全 | 几何与补全本身有多少收益 |
| B2 | B1 + 共享 DLSS5 | 分眼前增强是否改善一致性与观感 |
| B3 | B1 + 分眼局部 DLSS5 | DLSS5 是否真的改善洞区 |
| B4 | B1 + 原 PLAN 跨眼历史 DLSS5 | 虚拟历史是否优于单帧/真实时序 |
| B5 | 最优组合 + 冻结置信度合成 | 实际可交付输出 |

另外做同一 carrier 的 Feature18 开/关对照，保留相同 DLAA、曝光、输入和合成。只有验证开关确实改变 Feature18 执行后，才能把差异归因于 DLSS5。比较零 MV、正号、反号、正确几何 MV、reset 与不 reset；native ControlMask 参数块转发问题与本实验分开记录。

### 指标和初始验收门槛

所有方法使用同一份几何 mask，分别统计内部反遮挡、边界外推、前景边缘带、可信可见区。输出线性域 MAE/RMSE/PSNR、感知指标、边缘位移和原尺寸 crop。洞比例是几何属性，不能以非黑像素数量代替补洞质量。

眼间误差只在具有真实对应的区域比较；生成背景用共享层的表面坐标比较。视频测运动补偿后的残差变化，并排除真实新露出区域。记录每眼端到端 p50/p95 延迟、深度/补全/native 分项时间和显存。

以下为待验证的验收目标，不是当前成绩：冻结参数后的测试集上，B3/B5 相对 B1 的内部洞区 MAE 中位数降低至少 5%，并同时报告最差四分位和失败样例；可信区未开放修改时必须保持不变；眼间和时间误差相对 B1 不增加超过 2%。若 DLSS5 不达标则关闭对应阶段，保留改善后的几何与背景补全。

## 工程拆分与实施顺序

```text
src/dlss5/stereo/
  geometry.py        投影、覆盖率、Z-buffer、SourceMap/MV
  layers.py          共享前后景和观测来源
  completion.py      背景传播/补全接口
  history.py         真实时序背景缓存与 reset
  refinement.py      native DLSS5 候选和置信度合成
  pipeline.py        两眼生成与 SBS/TAB
tools/experiments/stereo_v2/
  scenes.py          有隐藏背景真值的场景生成器
  run.py             消融与逐帧 native 输入
  evaluate.py        分区、眼间、时间、性能指标
examples/cases/stereo_v2/<run_id>/
  config.json        固定参数和依赖版本/hash
  metrics.json       原始分区指标
  images/            输入、深度、各类 mask、两眼与差分
```

这些目录为规划，按实现阶段创建，避免空壳模块。第一阶段交付真实遮挡 oracle 和逐帧 MV 校准；第二阶段实现 B1；第三阶段跑 A/B/C 的 native 消融；第四阶段实现通过验收的组合及视频历史缓存。每阶段更新同一实验报告，展示全部失败用例。旧 `PLAN.md` 作为 V1 假设和历史证据保留。
